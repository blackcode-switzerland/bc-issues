## 8. Routes with no `bk` command (Phase 3 parity exclusions)

Established by walking `app/api/**` against the CLI command tree. These are the
only paths that will need to sit in `EXCLUDED_PATHS` in `lib/cli-parity.test.ts`:

| Path | Why excluded |
|---|---|
| `/api/auth/{nextauth}` | NextAuth handler — browser session machinery |
| `/api/auth/register`, `/api/auth/password-reset/*` | Browser sign-up / recovery flows |
| `/api/errors/client` | Client-error beacon (telemetry) |
| `/api/upload/blob` | Vercel Blob client-upload token handshake; the CLI *uses* it inside `bk upload` but it is not a REST resource |
| `/api/status`, `/api/status/errors`, `/api/status/errors/{id}` | Public status page feed; super-admin triage is exposed via `/api/super-admin/errors` |
| `/api/cli/authorize` | The `bk login` browser handshake (server-rendered, not called by the binary) |
| `/api/me/password/*` | In-app password change — session-only by design |
| `/api/openapi.json`, `/api/docs` | Phase-4 `410 Gone` deprecation stubs |
| `/api/changelog` | Public; covered by `bk changelog` — **not excluded**, listed here only to note it is annotated |

Everything else must carry a `routes` annotation on the cobra command that calls it.
