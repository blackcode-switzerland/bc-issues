  callers. invitations.ts imports it only to re-export it. DELETE IT FIRST.

This has been independently verified. Trust it.

## THE FAILURE MODE THIS PHASE ACTUALLY HAS

Every earlier phase failed loudly — a 500, a 42P01, a build error. Phase 4 fails
QUIETLY. A missing app_access row does not crash; it renders an empty workspace
list, which reads as "working correctly, nothing to show."

So verification must assert POSITIVE facts, not absence of errors:
  - THIS user sees THIS workspace, by name
  - a workspace flipped to invite_only DENIES a specific new member
  - the denial carries an actionable `suggestion`
  - after granting, the same user sees it

A green run that never asserts a specific workspace is visible has proven
nothing. This is the one phase where "no errors" is not evidence.
